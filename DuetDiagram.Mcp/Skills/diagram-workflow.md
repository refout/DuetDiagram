# 一次改动该怎么走

## 顺序

1. **先读一次摘要。** 摘要里有当前的版本号，改的时候要原样带回去；它同时告诉你图里现在
   有什么、哪些元素被固定住了、有哪些样式令牌可用。凭印象改是这一行里最常见的一种错。

2. **判断这一步改的是哪一类东西，再选工具。** 改「图里有什么、谁连着谁」是一类，
   改「看起来什么样」是另一类，改「怎么排」是第三类。三者各有各的工具，
   拿错工具不会报错，只会得到一个「这个动作不认识」。

3. **一次调用只做一件事。** 这些工具每次只接一个动作，不要指望把一串改动塞进一次调用里。
   要连着改好几处时，一处一次发——而每成功改一次版本号就往前一格，
   所以下一次带的版本号要是新的那一个。

4. **改完再读一次，或者校验一次。** 结构变更会让已经算出来的坐标失效，摘要里的布局描述
   要重读才是新的。一批改动都做完之后再校验，不要每改一步都校验一次。

## 常见错误

- **没带版本号。** 改图必须说明「我看到的是哪一版」。不带的话这次写入会被拒，
  回的是一份完整快照——先读一次，再带着版本号改。
- **手上的版本旧了。** 被拒时回的是差异或者快照。按它追平之后再改，
  不要原样重试同一次调用：重试大概率还是同一个结果。
- **撤销撤掉了别人的一步。** 撤销与重做走同一条历史栈，人和模型共用一条。
  撤之前先想清楚要撤的是哪一条，返回结果里会说明实际撤掉了什么。
- **样式令牌不在调色板里。** 会被拒绝，返回里会列出可用的那些，照那个列表选。
  放行一个不认识的令牌的话，渲染层会按默认样式画，而你以为样式生效了。
- **图层不是这份凭据能碰的。** 凡是点名了某个图层的写入都各判一次：改节点的图层归属、
  新建图层、改图层名、调图层次序、改这一层画不画、改这一层锁不锁。
  报的是「这个图层不许改」，换一个能改的图层或者换一份凭据。
- **这一层锁着。** 那是文档里的状态、不是凭据的事，报的是另一个码：元素挪不进锁定层，
  锁定层上的元素也挪不出去（两个方向都算改它）。处置是解锁，或者换一层放。
- **组合成环或者套得太深。** 都会被拒绝。要移的成员还挂在原来的容器里时先把它摘出来。
- **导出缺东西。** 导出是有损的，写不出去的东西会在返回里逐类列出。
  那个列表是空的**不等于**无损，它只说明这一档没有丢东西。

## 最佳实践

- 改标签文字属于结构那一类，不属于外观那一类。两者管的不是同一件事。
- 相对位置这一类约束求解器现在还不消费它：设完之后坐标不会变，别拿它当"把这两个并排"用。
- 布局参数改完不会自己重排。返回结果里会说明要不要让宿主重排，照那个标志做。
- 报错之后先看错误里的 `expected` 那一栏：它写的是"这边认为合法的是什么"，
  比那句描述更省一次往返。
