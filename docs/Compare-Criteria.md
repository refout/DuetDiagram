# 对比测试：判定口径

本文件把方案给出的四个阈值翻译成**可计算**的判定规则。

不先把口径定死就跑语料，会在评分阶段发现四个数都算不出来，而那时语料已经冻结、钱已经花了。

## 实验设计

### 三组而不是两组

方案原本写的是两组（DSL 对 Mermaid）。**两组不够**，原因是一个明显的混淆：

DSL 那一组必须配语法文档（否则模型没见过这种格式，等于让它裸猜），
而 Mermaid 那一组如果什么都不给，比的其实是"有文档"对"没文档"，而不是"DSL 对 Mermaid"。

所以我们跑三组：

| 组 | 内容 | 作用 |
|---|---|---|
| A | Mermaid，不给任何语法说明 | 基线 |
| B | Mermaid，给等量的语法参考 | **对照组**，用来剥离"有文档"这个因素 |
| C | DSL，给完整语法说明与示例 | 待评估方案 |

判读规则：

- C 明显优于 A，但 **B 也明显优于 A** → 提升来自"有文档"，不是来自 DSL，**不应保留 DSL**。
- C 明显优于 B → 提升来自 DSL 本身，才支持保留。
- C 与 B 相当 → 说明两种格式在"给了文档"之后没有区别，**保留成本更低的那个**（Mermaid 无需自造解析器）。

这一条判读是本次实验最重要的产出。方案里没有它，直接用 A 与 C 比会得出错误的结论。

### 双盲怎么做到

Mermaid 与 DSL 的文本形态一眼可辨，直接看文本做不了双盲。

做法是：**评分者看的不是原始文本，而是从生成结果解析出来的结构清单**——
节点列表（标识、标签、形状）与边列表（起点、终点、标签）。

结构清单剥离了格式特征，评分者看不出它来自哪种格式。
三个组的结果混合打乱后再分发。

装置在 `tools/CompareHarness`，命令是 `-- listings`，产物说明见 `reports/compare-blind/README.md`。

只投影到节点与边这一层还不够。实测发现清单里另有两处会自报组别——**标识的写法**
（一组用连字符、另一组用下划线，两边都不重叠）与**标签里的 `<br>`**——
两处都已整批抹平：标识换成流水号，换行标记换成空格。怎么发现的、抹掉了什么，
写在 `reports/compare-blind/README.md` 里。

这也符合"端到端准确率"的本意：评的是图对不对，不是文本漂不漂亮。

### 分组与人员

- 三个组各 50 条，共 150 份结果，混合打乱。
- 两名评分者各自独立评全部 150 份。
- 评分者需培训：先用 10 条不含在测试集里的样例统一尺度。
- 两名评分者的判定不一致率超过 20% 时，由第三方仲裁，并把分歧项补进培训材料。

## 四个指标的计算口径

### 一、端到端准确率

| 项 | 定义 |
|---|---|
| 分母 | **50**（该组的全部 prompt） |
| 分子 | 该 prompt 的全部检查项都被判定为通过的数量 |
| 解析失败怎么算 | **必然不通过**，计入分母 |

辅助指标同时记录：**平均检查项通过率**（逐项 0/1 后取均值）。

记录辅助指标是为了避免"差一项就归零"把差别抹平——两个组可能在全通过率上接近，
但在一项之差的比例上差距明显。

### 二、人工修正步骤

| 项 | 定义 |
|---|---|
| 分母 | **该组中解析成功的 prompt 数量**（解析失败的不参与，单列报告） |
| 取值 | 每个 prompt 从生成结果修到"可接受"所需的操作次数 |
| 汇总 | 取均值 |

**"一次操作"的粒度必须按下面这张表数，否则两个人数的结果能差一倍：**

| 操作 | 计步 |
|---|---|
| 改一个节点的标签 | 1 |
| 新增或删除一个节点 | 1 |
| 新增或删除一条边 | 1 |
| 改一条边的端点 | 1 |
| 改一条边的标签 | 1 |
| 改一个节点的形状 | 1 |
| 增删一个分组 | 2（建组 1，归入成员 1） |
| 改图的整体方向 | 1 |
| **移动节点位置** | **0**（布局是自动的，不属于语义修正） |
| **整体重排或调整间距** | **0**（同上） |

最后两行是关键：位置由布局引擎负责，把它算进"人工修正"会让所有格式一起变差，掩盖真正的差别。

### 三、首轮通过率

| 项 | 定义 |
|---|---|
| 分母 | **50** |
| 分子 | 人工修正步骤为 0 的数量 |
| 解析失败怎么算 | **必然不通过**，计入分母 |

### 四、解析错误率

| 项 | 定义 |
|---|---|
| 分母 | **50** |
| 分子 | 解析器拒绝的数量 |
| 判定者 | 自动，无需人工 |

自动判定要区分两种拒绝：

- **语法拒绝**：解析器报错，拿不到任何结构。
- **语义拒绝**：语法通得过，但引用了不存在的节点、或分组成环等。

两者都算解析错误，但**分开报告**——语法问题可以通过改语法解决，语义问题要改的是提示词或校验。

## 判定规则

对四个指标逐一比较 C 与 B（**不是与 A 比**）：

| 指标 | 达标条件 |
|---|---|
| 端到端准确率 | C 比 B 高出至少 15 个百分点 |
| 人工修正步骤 | C 比 B 减少至少 30% |
| 首轮通过率 | C 比 B 高出至少 20 个百分点 |
| 解析错误率 | C 比 B 低至少 50% |

- 四项中至少三项达标 → **保留 DSL**
- 两项达标 → 仅用于流式场景
- 一项或以下达标 → **砍掉 DSL**

若 C 与 B 的差距均在噪声范围内（例如两组各 50 条，差距小于 2 条），
即使达标也应当视为不达标——**50 条的样本量撑不起 3 个百分点的差距**。

## 检查项已经改写成谓词，但三个指标仍然只能靠人

上面三个指标都交给评分者判。2026-09-21 量过一遍「能不能改成机器判」，结论是**不能**：
检查项用「」引出的节点名，拿去和生成结果的标签做字符串比，子串命中约 60%，
最松的确定匹配（子序列）约 75%。剩下那 25% 是措辞差异而不是模型没做到，
而且三组少给分的比例不一样——差出来的部分会被算成格式的差别。
再松就得引入相似度阈值，而阈值取多少没有客观依据。

实测数据与十例对照在 `reports/compare-blind/checkability.md`。

**同一天，256 个检查项按那份报告的建议全部改写成了显式谓词**（同义词表 + 结构谓词，
写在 `tools/CompareHarness/prompts.json` 的每条检查项上，求值器在 `Predicate.cs`）。
结果在 `reports/compare-blind/predicate-report.md`，两条结论：

- **能自动重算的从一项变成两项**：解析错误率，以及谓词口径的端到端准确率。
  首轮通过率与人工修正步骤仍然算不了——它们问的是"还需不需要改"，
  而"不需要改"包含"没有多余的东西"，那不是任何一条检查项描述过的内容。
- **但端到端准确率这一项失去了区分力**。谓词只判"该有的在不在"，
  而给足语法文档之后，该有的东西两组都写全了：253 个检查项里只有 23 个
  在三组 150 份上不是全过，对照组 B 直接是 100%。
  判定门要的"C 比 B 高 15 个百分点"在谓词口径下**不可能达成**，与 C 好不好无关。

所以判定规则那一张表**仍然全部要人判**。谓词口径的那份数字不是判定门的答案，
它的定位是**回归网**：换模型、改提示词、动语法之后重跑，
它能把"该有的东西丢了"当场抓出来；它抓不出"多了不该有的东西"。

还有一条必须写在这里的局限：**谓词是拿这 150 份语料对着调出来的**。
凡是结构上明明做到了、而谓词判成没做到的地方都放宽了（每一条都记在
`predicate-report.md` 的"改写过文本的检查项"里）。所以那份数字可复现，
但它是"对着答案调过判据之后"的可复现，**不是独立测量**。
谓词与人的判读是否一致，要等人工评分才能校。

## 已知的局限

| 局限 | 说明 |
|---|---|
| 样本量小 | 每组 50 条，单条差异约等于 2 个百分点。方案给的阈值（15 / 20 个百分点）远大于噪声，但"刚好压线"的结论不可靠 |
| 单一模型 | 结论只对生成语料时用的那个模型成立。换模型需要重新跑 |
| 模型会更新 | 语料冻结之后模型仍可能被替换，届时结论的时效性需要重新评估 |
| 只有两名评分者 | 一致性统计的自由度很低，只能看粗略的一致性率，做不了正式的评分者间信度分析 |
| DSL 语法由我们自己定 | 语法设计水平直接决定结果。设计得差，结论会是"DSL 不如 Mermaid"，而那反映的是设计水平而不是 DSL 这条路 |

最后一条是最需要警惕的：**这个实验同时检验了"要不要 DSL"和"我们的 DSL 设计得好不好"两件事**，
而它分不清这两者。
