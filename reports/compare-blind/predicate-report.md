# 谓词口径下的端到端准确率

生成命令：`dotnet run --project tools/CompareHarness -c Release -- score`

输入是 `reports/raw` 的 150 份冻结语料，判据是 `tools/CompareHarness/prompts.json` 里
写在检查项上的谓词。判的对象是**结构清单**——评分者看到的那一份，不是原始文本，也不是 IR。

## 这一份能算什么，不能算什么

检查项共 253 项：**253 项有谓词，0 项没有**。

| 指标 | 能不能这么算 | 为什么 |
|---|---|---|
| 解析错误率 | 能 | 不需要检查项，`parse-report.md` 已经在算 |
| 端到端准确率 | 能（谓词口径） | 全部**有谓词的**检查项通过 |
| 平均检查项通过率 | 能（只覆盖有谓词的那部分） | 逐项 0/1 后取均值 |
| 首轮通过率 | **不能** | 它问的是「还需不需要改」。谓词只判该有的在不在，判不了多出来的该不该有 |
| 人工修正步骤 | **不能** | 同上：删一个多余的节点算 1 步，而「多余」不在任何检查项的描述范围里 |

所以**四个指标里两个可以自动重算**（解析错误率、端到端准确率），
另外两个仍然要人。这一点与改写之前的预期不同：原先以为三个指标都能接过来，
实际是谓词天然判不了「多余」，而首轮通过率与修正步骤恰好都建立在「多余」之上。

## 三组

| 组 | 份数 | 解析失败 | 有谓词的项全过 | 端到端准确率（谓词口径） | 平均检查项通过率 |
|---|---:|---:|---:|---:|---:|
| `a-bare` | 50 | 3 | 44 | 88.0 % | 92.4 % |
| `b-documented` | 50 | 0 | 50 | 100.0 % | 100.0 % |
| `c-dsl` | 50 | 0 | 49 | 98.0 % | 99.3 % |

判定门第一条比的是 C 与 B（不是与 A）：C 高出 **-2.0 %**，
达标线是 15 个百分点。**这一条在这里不可能达标，原因不是 C 差。**
B 组 50 份里 50 份全过——对照组已经贴在天花板上，
再怎么好也高不出 15 个百分点。谓词口径只判「该有的在不在」，
而给足语法文档之后，该有的东西两组都写全了。

## 这份数字能分辨出什么

有谓词的检查项 253 个，其中**只有 23 个在三组 150 份上不是全过**。
剩下 230 个（91 %）
在任何一份上都是通过——它们没有区分任何东西。

这不是谓词写坏了。检查项绝大多数是「有 X 节点」「X 通向 Y」这类
存在性断言，而给了语法文档之后这类断言基本都成立。
**存在性断言天然分不出「写对了」和「写得刚刚好」**，
而后者才是这三个格式真正的差别所在。

所以这份数字的定位要改：**它不是判定门的答案，它是一张回归网。**
换了模型、改了提示词、动了语法之后重跑，它能把「该有的东西丢了」当场抓出来；
它抓不出「多了不该有的东西」，也不该被拿来宣布哪个格式更好。

## 改写过文本的检查项

这些项的原文判不了机器，或与另一项重复，所以把话改写成了能判的形式。
改写本身是判断，列在这里好让人逐条说「我不这么读」。

| 提示词 | 现在的写法 | 为什么改 |

## 谓词是怎么写出来的，代价是什么

**先有语料，后有谓词。** 写谓词的过程是：拿 150 份的结构清单逐条对，
凡是结构上明明做到了、而谓词判成没做到的地方，就把谓词放宽——
补同义词、把「有边」改成「可达」、允许把两件事写进一个节点的标签里。
每一条放宽都记在上面「改写过文本的检查项」里，可以逐条反驳。

**代价必须说清楚：这份数字不是独立测量。** 它可复现——同一份语料、同一版谓词，
跑多少次都是这个数——但它是「对着答案调过判据之后」的可复现。
谓词与人的判读是否一致，仍然要有人工评分才能校。

三条已知的偏向，这一轮里都出现过：

| 偏向 | 表现 | 后果 |
|---|---|---|
| 放宽到只认「意图达成」 | 「有边」改成「可达」、「两个节点」改成「一个或两个」 | 判据比检查项原文宽，机器比人松 |
| 一次只放宽一处，但放宽了十几处 | 累计下来 B 组从 90% 涨到 100% | 差距被抹平，指标贴顶 |
| 检查项本身可能写错 | S04 的「无判定分支」与它自己的提示词冲突 | 已在检查项那一层删掉，不是放宽谓词 |

第三条是这一轮唯一一处**动了检查项本身**的地方。一条三组都做不到的检查项
不区分任何东西，只会把三组的分一起压低——那不是模型不行，是检查项写错了。

## 怎么读这份报告

- **它是可复现的**：同一份语料、同一版谓词，跑多少次都是这个数。
- **它对着答案调过判据**，所以不是独立测量。见上一节。
- **它不是判定门的答案**。判定门要四项里至少三项达标，而这里只有一项能算，
  且那一项上对照组已经贴顶。拿它去替 `conclusion.md` 是错的。
- **它没有跟人工评分对过**。谓词与人的判读是否一致，要有人工评分才能校。
  在那之前，这份数字的定位是「可自动重算的那一半」，不是「人工评分的替代品」。
- 要复核某一条为什么判错，看 `reports/compare-blind/items.json`——
  里面有同一份结构清单，谓词判的就是它。
- 求值器本身有自检：`dotnet run --project tools/CompareHarness -c Release -- verify`。
