# P0-09 取证报告：工具定义能否共用

- 验证对象：`Microsoft.Extensions.AI` 10.7.0 与 `ModelContextProtocol` 2.2.0 的工具抽象
- 验证时间：2026-09-20
- 验证程序：`tools/Poc/SharedTools`（命令行运行即复现全部结论）
- 结论：**共用可行，且应当共用。方案留的退路也成立，但它是巧合而不是保证。**

## 一句话结论

代理侧的工具可以由模型侧的函数**直接派生**，一份定义同时供两边使用，
名称、描述、参数约束逐字相同。方案原先担心的"两边要各自维护"并不必要。

## 桥梁在哪里

两个包各自有从方法签名推导工具声明的入口：

| 侧 | 入口 |
|---|---|
| 内部模型 | `AIFunctionFactory.Create(方法, 名称, 描述)` |
| 外部代理 | `McpServerTool.Create(方法, 选项)` |

关键在于**代理侧还有一个接受模型侧抽象的入口**：

```csharp
McpServerTool.Create(AIFunction function, McpServerToolCreateOptions options)
```

也就是说，先用模型侧的工厂建出函数，再把它交给代理侧派生工具。
两边从此指向同一个对象，声明不可能不一致。

## 共用一份的验证结果

| 检查项 | 结果 |
|---|---|
| 名称一致 | 通过（两侧都是 `diagram_edit`） |
| 描述一致 | 通过（两侧都是「按动作修改图结构。」） |
| 参数 schema 一致 | **通过，逐字相同，339 字符** |
| schema 非空 | 通过 |
| 参数名齐全 | 通过（`action` `nodeId` `reason` 三个都在） |

生成的参数约束长这样：

```json
{
  "type": "object",
  "properties": {
    "action":   { "description": "要执行的动作名", "type": "string" },
    "nodeId":   { "description": "目标节点标识",   "type": "string" },
    "reason":   { "description": "可选的原因说明", "type": ["string","null"], "default": null }
  },
  "required": ["action", "nodeId"]
}
```

可空参数被正确识别为可选（不在 `required` 里、带默认值），必填参数被正确列入。

## 退路的验证结果

方案给"两边各自维护"留了位置。实测同一份方法签名由两边**各自独立推导**，
结果**也一致**（473 字符逐字相同，含数组参数与三个必填项）。

但这条结论要看清它的性质：**两边恰好一致，是因为它们用的是同一套推导规则**，
而这两套规则由不同的包各自实现，未来任何一方调整推导方式都会让它们分叉。
共用一份则是结构上不可能分叉。所以：

- **共用一份：首选。** 一致性由结构保证。
- **各自维护：可用，但需要测试兜住。** 如果因为别的原因必须分开维护，
  必须补一条测试断言两边的 schema 逐字相同，否则某天升级依赖之后会静默分叉，
  表现为"模型能调通的工具代理调不通"。

## 一个互操作注意点

可空参数生成的是 `"type": ["string", "null"]`，即 **JSON Schema 的数组形式**。
这是较新的写法，一些老的校验器只认 `"type": "string"` 加 `"nullable": true`。

外部代理用不同的实现接入时，这个形式可能被拒绝。接入阶段需要实测一次，
不接受的话要么改写成老形式，要么在文档里要求对端升级。

## 尚未验证

| 项 | 说明 |
|---|---|
| 真实模型的调用 | 只验证了声明的推导与一致性，没有真的让模型调用这个工具 |
| 真实代理的端到端调用 | 代理侧的调用需要经过服务端与传输，本验证只到声明层 |
| 行为一致性 | 代理侧的工具由同一个函数实例派生，行为一致是由结构保证的，但没有实际跑一次来确认 |
| 八个工具同时注册 | 只验证了单个工具，没有验证八个一起注册时的名称冲突与顺序 |

## 复现方式

```bash
# 完整验证
dotnet run --project tools/Poc/SharedTools -c Release

# 打印两个包的公开接口清单
dotnet run --project tools/Poc/SharedTools -c Release -- --api
```

## 对后续实现的约束

1. **工具只定义一次**，放在命令层之上、两侧之下，由模型侧函数向代理侧派生。
2. **如果将来不得不分开维护，必须补一条 schema 逐字相同的断言**，
   否则依赖升级会让两侧静默分叉。
3. **接入外部代理时要实测可空参数的 schema 形式**是否被对端接受。
