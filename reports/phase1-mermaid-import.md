# P1-09 Mermaid 导入：结论与取证

## 验收口径达成情况

| 口径 | 要求 | 实测 |
|---|---|---|
| 导入语料 | 97 份流程图全部导入，无致命失败 | **97 份全部导入**，另外 3 份图类型不对（都在 a-bare 组），解析器整份放弃并记诊断 |

## 耗时与分配

规模是 1000 节点、950 条连线、20 个子图、带 `style` 与 `classDef`。三段分开测，
因为它们的开销差一个量级，合成一个数之后不知道该优化哪一段。

| 段 | 均值 | 误差 | 每次分配 |
|---|---:|---:|---:|
| 词法 | 1.44 ms | ±0.20 ms | 1 005 KB |
| 词法 + 语法 | 9.35 ms | ±0.33 ms | 2 962 KB |
| 词法 + 语法 + 映射 | **28.43 ms** | ±1.11 ms | **18 920 KB** |

三条关于数字本身的说明：

1. **映射那一段比前两段加起来重得多，而且是重在分配而不是耗时。**
   它比"词法 + 语法"多花 19 毫秒，却多分配 15.9 MB——分配量的倍数远高于耗时的倍数。
   这与 Phase 0b 的结论是同一条（后续压分配而不是压耗时），所以下一个优化点在这里，
   不在解析器。参照：千节点布局每次分配 10 MB。
2. **词法那一段的绝对值不值得解读。** 1.44 毫秒里大半是分配（一兆字节的记号对象），
   而分配耗时受 GC 影响，短作业下误差棒相对值偏大。
3. 上表取中作业（`MediumRun`，15 次迭代、2 次启动）。短作业的均值也在输出里
   （映射 27.98 毫秒），两者差 1.6%，远小于短作业自身的误差棒——
   这也说明用短作业的数字比对会误判退化。

## 两个待定项的定论

**一、`-->|"text"|` 的引号剥不剥？剥。**

查证方式是读 Mermaid 自己的语法文件（`flow.jison`），不靠猜：

```
<string>[^"]+   { return "STR"; }     ← 引号之间的内容作为 STR 返回，不含引号
<string>["]     this.popState();
<*>["]          this.pushState("string");
```

而 text 状态里的 `TEXT` 记号明确排除了引号（`[^\[\]\(\)\{\}\|"]+`），
所以 `|"已处理"|` 必然走字符串状态；边标签的语法 `PIPE text PIPE` 直接接受 `STR`。
**引号是定界符，不显示。**

于是改解析器而不是改语法参考：两种写法（竖线定界与 `A -- "text" --> B`）同一个机制，
两处都补上剥引号，且只剥最外层一对。含逗号、括号这类会打断语法的字符时引号**必须**加，
所以它不是"模型写错了"。

语料里这个写法命中 2 份 10 处，都在 `b-documented`，改动代价为零。

**二、未映射的原始片段存在哪里？不存。**

方案的风险缓解写着「宽松模式 + 原始片段保留」，这里**偏离它**（已记进 `AGENTS.md`
的「与方案的已知差异」表）。理由是原始片段有个错误模式：

> 片段只在元素未被改动时有效。用户或模型改过那个节点之后，片段就成了旧文本，
> 而导出时再吐出来会把旧内容复活——两个哈希都没变，这种错没有任何地方会报。

放进不计哈希的 `NodeDef.meta` 恰好会掩盖这个问题。所以认不出的内容只进导入报告，
并如实说明"这一条不会被导出"。P1-10 的往返口径随之定为
**「同一份 IR 走一圈还是同一份 IR」**，不是文本逐字节一致。

代价是导入→导出之后 `linkStyle`、`click` 这类东西找不回来。**这是明说的损失**，
报告里有一条记录，用户看得到——与"悄悄丢掉"是两回事。

## 导入期的两条消歧规则（与 DSL 侧同一套）

两条规则两边必须一致，否则两种格式的对比量到的是实现差异而不是格式差异。

**子图被当成连线端点时，节点那一份丢掉。** 解析器读到连线会顺手给两端各造一个节点，
于是 `subgraph ODS` 之后写 `ODS --> DWD`，同一个名字既在子图表里又在节点表里。
丢掉节点那一份：Mermaid 渲染的就是两个子图框之间的连线，而且节点与组合共用标识命名空间。
丢掉要留记录——用户看到的是"我写的节点怎么不见了"，答案只有报告能回答。

**成员表按父级重推，而且要含嵌套子图。** 语法树的成员表里**只有节点**，
嵌套子图不在其中（子图的父级能反向指认出来，但成员表里没有）。
IR 的约定是"成员里既有节点也有子组合"，照抄会让外层组合的成员表与父级字段对不上。

## 一个依赖，以及替它站岗的用例

导入层**没有补隐式节点**——它依赖"解析器读到连线时会顺手给两端各造一个节点"。
那条性质属于 P1-08，将来可能变。变了却没人知道的话，表现是边悄悄地少一条，
而少一条线不容易被归因到解析器改了行为。

所以有一条用例逐份检查每条边的两端都有落点。它比校验器报的错更直接：
会指出是哪个端点没落地。
