## 两套装置的分工

| 装置 | 拉起来的是什么 | 跑在哪 |
|---|---|---|
| `DuetDiagram.Mcp.Tests` | 大部分用例起进程内的服务端；标准输入输出那一组拉真的子进程 | CI 的 Test 一步，另按分类单列门禁 |
| `tools/McpHarness` | **真的服务端可执行文件**：标准输入输出由它拉子进程，网络那一档由它带 `--http --workspace --token` 起子进程再连上去 | CI 的「MCP 实机验收」一步，也可以人工跑 |

**为什么要两套。** 用例走进程内建的服务端，验的是"这一层的逻辑对不对"；
装置走命令行，验的是"拿出去能不能用"——参数解析、端口、日志改道三样都在那条通路上，
而它们只有真的起一次才发现。本条的第三条结论就是这么发现的（见下）。

```bash

```

## 八条判据的结果

全部由**自建客户端**（`tools/McpHarness`）在协议层验的，跑的是真的服务端可执行文件。

| # | 判据（§15.2） | 结论 | 观测到的 |
|---|---|---|---|
| 1 | 协议一致 | 通过 | 两条传输各 8 个工具，名称、描述与参数 schema 逐字相同 |

| 4 | 409 + diff | 通过 | 409 带 `VERSION_CONFLICT` 与一份内容（`diff` 是个对象） |

### §15.2 里的「accepted=false 处理」没有落点

清单上第 9 项是「accepted=false 处理」，对应方案 §7.3 的
「`initialize` 请求带 clientState、响应回 `accepted` 与一个 `reason`」。

**这一条在这条协议通路上不存在**，不是没做：当前协议版本用服务发现请求取代了初始化请求
（P0-05 已经记过），会话状态随**每条请求**带上来、服务端每次现读现判。
所以不存在"一次协商被接受或被拒绝"这件事，只有"这一条请求的声明与文档对不上"。

替代口径就是 §7.4 那四行：对不上时回的是**差异或快照**（网络那一档 409 加内容），
不是 `accepted=false` 加 `reason`。这一条**记成已知差异，不写成「已通过」**，
也已写进 `AGENTS.md` 的已知差异表。

## 多 agent 并发那一档

判据是**文档仍然校验通过且版本号单调递增**，不是"没有抛异常"——
抛异常那条路早就被传输层那一道预判挡住了，漏网的是「两个都成功，后一个把前一个盖掉」：
那件事两个调用方都不报错，版本号还照样往前走。

所以核的是四件事，缺一条都放过那种损坏：

1. 成功的次数等于十个 agent 各写两次（20 次）；
2. 成功的版本号正好是 `1..20` 的连续整数——**重号**说明两条写入落在同一个版本上，
   **跳号**说明有一版没人认领；
3. 回到文档本身：最终版本 20、节点 20、整体校验零问题。前两条核的是"调用方各自看到了什么"，
   这一条核的是"文档最后是什么样"；
4. 冲突确实出现过。一次都没有的话，说明十次写入是排着队完成的，
   那样这一档验的东西与顺序跑没有分别。

**十个客户端齐步走。** 每个 agent 先读一次版本，十个都到齐了再一起写。
不齐步走的话，"读到同一个版本"这件事由调度决定，十次写入可能根本不在同一瞬间，
而这一档要挡的正是"同一个版本上同时有多个写入方"。

**每个 agent 一份凭据。** 限流是按凭据算的，十个人共用一份的话，
这一档会以限流的形式失败，而失败看起来像并发出了问题——排查方向会被带偏。
进程内那一组同理，频次上限抬到了这一档够用的高度。

冲突有两种形状，两种都在：传输层回 409（进协议之前就被挡住，带差异），
命令层回一条带错误码的工具结果（落在预判与门锁之间那个窗口里）。
装置两个数都记，用例两条都逐条核过。

```bash
dotnet test --project DuetDiagram.Mcp.Tests/DuetDiagram.Mcp.Tests.csproj -- --filter-trait "Category=MultiAgent"
```

## 实机验收发现的三处实现缺口

三处都不是新功能，是**装置拿真的可执行文件跑才露出来的**——进程内的用例各有各的绕过方式。

### 一、两条传输回的会话应答不一致（已修）

标准输入输出那条把 `SessionAck` 挂进能力扩展位，网络那条只挂了服务端信息与那段话。
同一个客户端换一条传输就读不到应答，而它会以为自己没连上。
§7.3 的应答是握手的一部分，而"两条传输说的是同一段"这件事在服务端那段话上已经立过。

修法是把那段选项合成一处（`DiagramMcpServer.ConfigureOptions`），两条传输都调它。
这与 Skill 那条同源：两份实现迟早对不上，而对不上的那一处谁都不会报。

### 二、网络那一档的审计没有出口（已修）

命令行起网络服务端时没有传诊断出口，于是审计记录与命令层的告警都写进一个丢弃一切的实现。
表现是"审计功能已经有了"，而跑起来一条都读不到。
**这一条只有拿真可执行文件跑才会发现**：进程内的用例都传了一个收集器，所以它一直没露出来。

修法是加一个写标准错误的出口（`StandardErrorDiagnostics`）并在命令行上接上。
写标准错误而不是标准输出：容器与守护进程的惯例里标准输出是"程序的结果"，
而标准输入输出那条传输上它被协议占着——两条通路共用一个去处，
免得哪天有人在另一条上写错地方。

### 三、命令行印出来的地址多一个斜杠（已修）

`host.Address` 自带一个结尾的斜杠、`HttpHost.McpPath` 自带一个开头的斜杠，
直接拼出来是 `http://127.0.0.1:38123//mcp`。Kestrel 自己会把双斜杠折掉，
所以它一直没造成故障——但那一行是给人看的，而人照着它去配客户端就会写错。

## 真实代理那一步：**未验**

§14.3 的判据写的是「Codex CLI / Claude Code 可读写」，那两样是**别人的实现**——
它们对可空参数的 schema 形式、对扩展位的读法各有各的容忍度。
自建客户端验的是协议层能通，替代不了这一条。这一条**不写成「通过」**。

这台机器上两个命令行都在（`claude` 2.1.229、`codex` 0.147.0），凭据文件也在，
所以"装不上"不成立。跑不通的是它们各自的模型端点：

| 命令行 | 结果 | 证据 |
|---|---|---|
| Claude Code 2.1.229 | **跑不通** | `claude -p` 第一次探针回了内容，随后同一条命令回 `API Error: 402 Insufficient Balance`；重试两次（一次带 MCP 配置、一次不带）都是同一个错误 |
| Codex CLI 0.147.0 | **跑不通** | 它的 provider 指向 `http://127.0.0.1:15721/v1/responses`，那个端点上没有服务，5 次重连之后报 `stream disconnected before completion` |

装置这一侧已经备好，端点可用之后接上去是一条命令：

```bash
# 印出服务端命令行，以及 Claude Code 与 Codex CLI 各自的配置写法；
# 顺带把那份文档写出来（标准输入输出那一档要一个已经存在的文件，不存在直接起不来）
dotnet run --project tools/McpHarness -c Release -- agent
```

**装置齐了不等于测过了。** 这一条与 P1-14 的人工评分、P2-13 的真人数据同一类：
要人看着跑。跑没跑成、结果如何，由这一份报告照实记——所以上面写的是「未验」。

## 遗留

1. **真实代理那一步未验**（上面）。它挡住的是「别人的实现对可空参数的 schema 形式、
   对扩展位的读法容忍不容忍」这件事，自建客户端测不出来。
2. **并发那一组用例出现过一次偶发失败，已修。** 根因是断言写成了「传输层回过 409」
   （`conflicts > 0`），而一次冲突落在传输层还是命令层由时序决定——两种都是对的，
   所以那个断言本身是非确定的。改成确定不变量：**两种冲突加起来至少 `AgentCount - 1` 次**。
   十个客户端齐步走之后，第一轮十个都报同一个版本，只能有一个成功、其余九个必被拒，
   这个下界与调度无关。同时把齐步走的等待时限放宽、进程内那一组的频次上限抬高
   （十个人各一份凭据，额度本来够，抬高是免得这一档以限流的形式失败、
   而限流看起来像并发出了问题）。改完连跑 56 次全绿。
3. **`tools/Poc/McpTransport` 与 `tools/Poc/SharedTools` 随这一条删掉了。**
   前者验的是协议库本身能不能支撑三条传输与自定义会话字段，后者验的是一份工具定义能不能两处共用；
   两份结论都固化了（落点是真实的两条传输与 `Category=ToolParity`），
   留着就是同一件事的两份实现。要复核当初那份对**库**的取证，从 git 历史里取回。
   `tools/Poc/LayoutCandidates` 不动：它服务的是布局引擎主选那个还开着的决策门。
4. **跨机器传输没做**：TLS、多实例共享变化源。现在只验了回环地址上的网络传输。
