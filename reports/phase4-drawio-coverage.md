# Phase 4：draw.io 覆盖率取证

## 一、结论

**覆盖率 86.3%，达到方案 §14.3 的「Phase 4：draw.io 覆盖 ≥ 85%」判据。**

- 分母：117 条能力（来自 draw.io 公开能力面，取数时间 2026-09）。
- 有 88 条、部分 13 条、无 16 条。
- 覆盖率定义为「（有 + 部分）/ 总数」= (88 + 13) / 117 = **86.3%**。
  另算加权口径（有 + 0.5×部分）= 80.8%，一并报出，不混入主数。
- 门禁：`dotnet run --project tools/CoverageAudit -c Release` 退出码 0。

「部分」算覆盖，理由是 draw.io 覆盖判的是「这一项能力本工具到底有没有」——
部分支持即已支持，只是缺一半；这与「有无」的语义一致。加权口径单独保留，
是因为「部分」与「有」对下游打磨的工作量不同，不能假装相等。

**取证装置比数字重要。** `tools/CoverageAudit` 不进解决方案文件（与 `tools/LocCounter`、
`tools/CompareHarness` 同一口径），分母与每条判定都写死在 `Matrix.cs` 里，换一个人跑同一个
装置应得到同一个数。每条要么指向一份证据（仓库文件 + 可复跑命令），要么写明为什么不做——
分母不自我实现。

## 二、取证方法

```
dotnet run --project tools/CoverageAudit -c Release              # 印逐档计数与覆盖率，退出码 0/1
dotnet run --project tools/CoverageAudit -c Release --list-missing  # 列出全部「无」带理由
```

装置会顺带核对每条「有 / 部分」的证据文件是否真在仓库里，缺失会逐条告警
（本轮核对：0 条缺失）。`--list-missing` 列出 16 条「无」及每条的理由，那一段是 Phase 5 的输入。

分母是 draw.io 实际能力面，按下述几档取——draw.io 是一个完整编辑器，这几档都是它公开能力面的
组成部分，与任务卡片约束一致：

形状 / 连线 / 容器 / 文本 / 导出格式 / 布局 / 编辑交互 / 画布与页面 / 协作与版本 / 面板与工具栏。

## 四、明细（有 / 部分 / 无，逐条带证据或理由）

### 有（88 条，证据为仓库文件）

形状：矩形、圆角矩形、体育场形、菱形、椭圆/圆、六边形、平行四边形、圆柱、自定义形状（路径 M/L/A/Z）。
连线：直线、正交折线、曲线、端点箭头多款、线型三款、连线宽度、连线颜色、边标签三位置、边标签换行、
端口四向、双向箭头。
容器：分组/组合、图层可见锁定、多页面、层内次序约束。
文本：纯文本、粗体、斜体、下划线、删除线、字号、颜色、段落对齐、行内对齐、数学公式、自动换行、多段落。
导出：SVG、PNG、PDF 矢量、Mermaid、矢量文本、位图含文字、透明背景 PNG、逐页导出。
导入：Mermaid 文件、模板片段插入。
样式：填充色、描边色、描边宽度、不透明度、调色板/令牌预设。
布局：自动分层、同层、对齐、层内次序、超时降级、预算重试。
编辑交互：拖拽移动、框选、连线重连、边编辑、右键菜单、就地编辑、撤销重做、缩放平移、多窗口、只读锁、
节点字段编辑、边字段编辑、删除元素、节点固定位置。
画布与页面：背景色、页面尺寸、页面标签、属性面板。
协作与版本：版本号、结构哈希、冲突 409、审计日志。
面板与工具栏：工具栏、菜单栏、调色板、形状库、模板、文本预设、图层、诊断、约束编辑器。

（每条对应的证据文件见 `tools/CoverageAudit/Matrix.cs`，由装置逐条核对存在。）

### 部分（13 条，缺哪一半写在备注）

- 流程图标准符号集：决策/过程/终止可覆盖，文档/数据等无预设，需自定义路径近似。
- 星形/多边形（>6 边）：靠自定义路径，无预设入口。
- UML 专用形状：自定义路径能做几何近似，不带动词语义。
- 连线自动避让路由：正交走线由布局给出，拖拽实时绕障未做，pinnedEdges 未接渲染。
- 连线路径点：折点写进 sidecar，布局与渲染尚未消费。
- 浮动连接：按端点连接，连到几何边界任一点未做。
- 容器自动撑大：组合有成员语义，但尺寸不随子元素自动增长（坐标由布局决定）。
- 组合折叠/展开：结构存在，折叠态渲染未做。
- 字体族：字体名映射到系统字体，未做字体选择 UI。
- 文本垂直对齐：仅水平对齐。
- 圆角半径可调：角由形状决定，未开放可调半径字段。
- 布局约束相对位置：set-place 已落 IR/哈希/校验，求解器尚未消费。
- 网格显示开关：有网格字段，吸附辅助线未做。

### 无（16 条，为什么不做）

1. 形状·云形 —— 无预设，方案未要求。
2. 形状·图片/图标占位 —— 不支持嵌入图像。
3. 容器·泳道/分区 —— 无 swimlane 预设。
4. 容器·Z 序 —— 节点集合顺序进不了任何哈希，效果不可观测，无 z-order 字段。
5. 文本·项目符号/编号列表 —— P4-14 段落级对齐与列表仍没有入口。
6. 文本·行间距 —— 未做。
7. 文本·竖排/RTL —— 未做。
8. 导出·HTML —— 未做。
9. 导出·draw.io XML —— 读写的是本仓自己的 IR 与 DSL，不兼容 draw.io 格式。
10. 导出·JPEG —— 位图只走 PNG。
11. 导入·draw.io XML —— 不读 .drawio 格式。
12. 导入·图像 —— 未做。
13. 导入·SVG —— 未做。
14. 导入·DSL —— DSL 去留未定（决策门 1），入方向仅解析未接生产入口。
15. 样式·渐变填充 —— 无 Gradient 字段。
16. 样式·阴影 —— 未做。

其中第 9/11 条（draw.io 格式的读与写）是「刻意不做」而非「还没做」：本仓有自己的 IR 与 DSL，
去兼容 draw.io 的私有 XML 是另一份工程量，不在 Phase 4 范围。第 14 条卡在决策门 1。其余是
P4-14 等任务的遗留或方案未要求。

## 五、与任务清单的出入

- 计划里 `modify` 列了 `MenuRegistry.cs`、`MermaidImporter.cs` 等，本条实际没动它们：
  `MenuRegistry` 与 `MenuEntries` 是同一套注册表的两边，菜单条目落在 `MenuEntries.cs`；
  `MermaidImporter` 本就在，本条只从生产代码调到它（P4-19 做的）。
- 装置不进 `DuetDiagram.slnx`，与 `tools/LocCounter` 同口径——它是调查工具，没有可被产品
  代码引用的接口。
- 分母比「本仓已做之事」宽：刻意纳入 draw.io 的真实能力面（含本仓没做的那一档），
  否则覆盖率是一个自我实现的数。

## 六、后续（Phase 5 的输入）

16 条「无」里，值得在打磨阶段补的有：列表（P4-14 已欠）、渐变/阴影（样式表现）、图片嵌入
