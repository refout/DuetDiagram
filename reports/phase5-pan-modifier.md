## 现象

产品方报的是**画布无法拖动**。方案给画布定的平移手势是**中键拖拽**或**空格加左键拖拽**
（P2-02 卡里写死的那两条），而空格那一条在两种最常见的状态下**静默失效**。

## 改前的读数

探针量的是「按着空格、左键从画布中心拖 (50, 20)，视口位移了多少」——
视口位移就是画布真的动了多少，不是「事件有没有送到」。

| 场景 | 焦点在哪 | 视口位移 | 结论 |
|---|---|---|---|
| 窗口刚打开，直接空格加左键拖 | **没有任何控件有焦点** | 0 | 不动 |
| 点过工具栏上任意一颗按钮之后 | `Button(全选)` | 0 | 不动 |
| 先点一下画布，再空格加左键拖 | `DiagramCanvas` | (50, 20) | 动 |
| 中键拖拽（任何状态） | 无所谓 | (50, 20) | 动 |

两条硬证据：**窗口刚打开时焦点是「无」**（不是画布）；**点过工具栏按钮之后焦点落在那颗按钮上**
（不是画布）。第三行说明了原因——只有焦点正好在画布上时，空格才到得了画布。

## 根因

画布原来是在自己的 `OnKeyDown` / `OnKeyUp` 里收空格的。**键盘消息只发给有焦点的控件**，
所以这条实现隐含了一个前提：焦点得先落在画布上。画布只在**指针按下**时把焦点收过来，
于是「先按空格再拖」这一路在两种状态下都收不到空格：

1. 窗口刚打开——谁都没有焦点，画布也没被点过；
2. 点过工具栏上任何一颗按钮——焦点跑到那颗按钮上了。

两种都是用户上手第一分钟就会走到的状态，而表现是"按着空格拖，画布一动不动"。
顺带还有一条更难察觉的：**焦点在按钮上时按空格会把那颗按钮按下去**（实测按一下「全选」，
选中集合从 0 变成 5），也就是说用户想拖画布，结果顺手改了一次选中。

## 改法

**空格改在窗口那一层用隧道读**（`DiagramCanvas.OnAttachedToVisualTree` 往 `TopLevel`
挂 `KeyDownEvent` / `KeyUpEvent`，`RoutingStrategies.Tunnel`）。走隧道还顺手挡住上面那条副作用：
画布认下空格时把它标成「已处理」，焦点所在的那颗按钮因此不会被空格按下去。

**但空格不是画布专属的**——它同时是按钮的「按下」键与文本框里的一个字符，所以不能一概抢过来。
规则一条，三条分支：

- 焦点在**文本框**里（就地编辑标签那一层、属性面板上的字段）→ 归文本框，画布不碰；
- **指针在画布上**，或者**画布拿着焦点** → 归画布；
- 其余时候（指针在别处、焦点在某颗按钮上）→ 留给聚焦的控件，
  键盘用户 Tab 到某颗按钮之后按空格仍然能按下它。

已经按下的那一下必须继续归画布，否则抬起消息回不到这里，空格会一直留在「按着」。

**光标跟着这个状态走**：空格按下时画布的光标变成「四向箭头」。按着空格而光标没变的话，
用户不知道已经按上了。

窗口失去激活（Alt+Tab）时收不到抬起消息，所以窗口一失活就把这个状态清掉。
`OnLostFocus` 里那一条兜底清掉保留着。

## 判据

五条新用例，都在 `Category=Canvas` 里：

| 用例 | 量什么 |
|---|---|
| `Space_drags_the_view_before_anything_has_been_clicked` | 刚打开、焦点是「无」时，空格加左键拖要位移 |
| `Space_drags_the_view_while_a_toolbar_button_has_focus` | 焦点在工具栏按钮上时，空格加左键拖要位移 |
| `Space_over_the_canvas_does_not_press_the_focused_button` | 指针在画布上时按空格：那颗聚焦的按钮**不许**被按下，视口要位移 |
| `Space_over_a_button_still_presses_it` | 指针在按钮上时按空格：那颗按钮**要**被按下（上一条的对照） |
| `Space_while_a_text_box_has_focus_does_not_drag_the_view` | 焦点在文本框里时，空格加左键拖**不许**平移 |

后两条是**对照**。少了它们，一个「把空格整个吞掉」的实现也能全绿——
而那会把键盘用户按空格激活按钮的路堵死，也会让标签编辑器里打不出空格。

**「把修复撤掉它就红」验过。** 把 `DiagramCanvas.cs` 单独 stash 掉、跑 `Category=Canvas`：
17 条里**恰好红 3 条**，就是上表前三行；后两条对照照样绿。

## 顺带量到的一件事：水平滚轮被丢掉了

查这一条时顺手量了滚轮。`OnPointerWheelChanged` 只看 `e.Delta.Y`：

| 输入 | 视口 |
|---|---|
| 起始 | scale 1.631，offset (215.1, 24) |
| 水平滚一格 `(1, 0)` | scale 1.631，offset (215.1, 24)——**什么都没发生** |
| 垂直滚一格 `(0, 1)` | scale **1.8756**（×1.15，以光标为锚点） |
| 垂直滚一格 `(0, -1)` | 回到 1.631 |

**垂直那一轴是方案定的**（P2-02：滚轮以光标为锚点缩放），没动。
**水平那一轴是整条丢掉的**——触控板上横着划两指，画布既不平移也不缩放，什么反应都没有。
触控板上两指上下滚是缩放而不是平移，这是方案定的行为，但它与多数绘图软件相反
（那些是滚轮平移、Ctrl 加滚轮缩放），而笔记本用户没有中键。
**要不要改是产品决定，这一条没有改**，只把量到的读数记在这里。

## 遗留与没验的

1. **没有人看着跑过。** 五条判据都是无头宿主里的读数（视口位移、选中集合），
   真机上手指按着空格拖的手感、光标变没变、Alt+Tab 回来之后还顺不顺手，装置判不了。
   这与 P1-14 / P2-13 / P3-16 / P4-22 / P5-07 / P5-08 同一类：**装置齐了不等于测过了**。
2. **Alt+Tab 那一路没有判据。** 失活时清掉空格状态那段代码只在代码里，
   无头宿主里 `Hide()` 不报 `Deactivated`（实测 `IsActive` 一直是 `true`），
   所以它**只有代码路径，没有判据**。真机上要验的是：按着空格 Alt+Tab 出去再回来，
   左键拖空白应当还是框选。
3. **手势本身没有可见的提示。** 除了按空格时画布光标变成四向箭头之外，界面上没有任何地方
   写着「空格加左键拖动是平移」——那句说明只写在画布的可访问说明里（读屏才听得到）。
   用户得先知道这个手势，才谈得上用得顺手。要不要在界面上给个提示是产品决定。
4. **指针必须先到画布上，空格才归画布。** 指针在别处时先按住空格、再移到画布上拖，
   这一下不会平移（空格没被画布认下）。要按两次空格才顺。这是「不抢按钮的按下键」
   那条规则的代价，规则本身是有意的。
5. **框选、拖节点、连线那几条手势一条都没碰。** 这一条只改了空格的读取位置与归属规则，
   左键拖空白的框选行为一个字没动（`A_plain_left_drag_leaves_the_view_alone` 仍然绿）。
