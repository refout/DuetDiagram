# 对比测试语料

本目录是 DSL 与 Mermaid 对比测试的**冻结语料**。

**不要手工修改任何文件。** 语料一旦被改动，比较就不成立——两侧结果必须是在同一时间、
同一模型状态下产生的，事后修补会让结论失去意义。需要重新生成时用下面的命令整体重跑。

## 它是什么

同一批 50 条提示词，在三个不同条件下的模型原始响应：

| 目录 | 组 | 条件 |
|---|---|---|
| `a-bare/` | 基线 | Mermaid，不给任何语法说明 |
| `b-documented/` | 对照 | Mermaid，给等量的语法参考 |
| `c-dsl/` | 待评估 | 本项目的 DSL，给完整语法说明与示例 |

为什么要三组而不是两组：DSL 那组必须配语法文档，而 Mermaid 那组如果什么都不给，
比的就是"有文档"对"没文档"，而不是"DSL 对 Mermaid"。
判读时应当拿 `c-dsl` 与 `b-documented` 比，而不是与 `a-bare` 比。

完整的判定口径见 `docs/Compare-Criteria.md`。

## 怎么生成的

- 模型：`GLM-5.3-Flash`（强制思考，不可关闭）
- 时间：2026-09-20
- 命令：

```bash
dotnet run --project tools/CompareHarness -c Release -- generate --parallel 4
```

生成器逐条幂等，中断后重跑不会重复调用已完成的条目。

## 文件结构

每个文件对应「一条提示词 × 一个组」，路径是 `{组}/{提示词标识}.json`：

```json
{
  "arm": "c-dsl",
  "promptId": "S01",
  "tier": "simple",
  "model": "GLM-5.3-Flash",
  "startedAt": "...",
  "elapsedMs": 5793,
  "request": { "model": "...", "messages": [ ... ] },
  "content": "模型输出的图代码",
  "reasoningContent": "模型的思考过程",
  "finishReason": "stop",
  "usage": { "prompt_tokens": 641, "completion_tokens": 528, ... },
  "rawResponse": { ... }
}
```

三个字段值得注意：

- **`request` 保留了原始请求体**，包括当时用的系统提示词。
  将来发现提示词写错了，可以据此判断影响了哪些条目。
- **`content` 与 `reasoningContent` 分开存**。这个模型强制思考，推理内容往往比正文长几倍，
  混在一起会看不清模型到底输出了什么。
- **`usage` 记录了用量**，便于事后核算花费。

## 规模

| 组 | 条数 | 提示 token | 完成 token | 其中推理 | 平均耗时 |
|---|---:|---:|---:|---:|---:|
| `a-bare` | 50 | 6,104 | 71,120 | 62,858 | 17 秒 |
| `b-documented` | 50 | 39,204 | 92,948 | 81,823 | 22 秒 |
| `c-dsl` | 50 | 33,404 | 80,973 | 71,364 | 18 秒 |

合计约 32 万 token。方案给的 30 美元预算是实际需要的百倍以上。

推理 token 占了完成 token 的八成以上——这是强制思考模型的固有开销，
做成本估算时不能按普通模型的口径算。

带文档的两组提示 token 分别是基线的六倍与五倍，那部分就是语法文档本身。
**这是 DSL 的真实成本之一**：模型训练数据里没有这套语法，每次调用都要重新告诉它。

## 关于生成过程中的两次超时

`a-bare/C07`（容器编排拓扑，唯一需要嵌套分组的条目）前后超时两次：
先以五分钟上限超时，放宽到十分钟仍超时，第三次以二十分钟上限跑通，
**实际只用了 81 秒**。

它同组其它复杂条目在 138 到 147 秒之间，所以 81 秒完全正常。
结论是**前两次超时属于服务端偶发停滞，而不是模型真的算了那么久**。

这条记录下来的用处是：**遇到超时不要急着归因到提示词或模型上**。
当时的第一个推断是"A 组的提示词没有嵌套分组的参考，所以模型反复斟酌"，
而那个推断被第三次的 81 秒直接否定了。生成器里的超时上限现在设在二十分钟，
足以区分"正常但慢"与"服务端卡住"。

## 一条使用提示

`content` 字段里的图代码**可能带也可能不带 Markdown 代码围栏**——同一条提示词
要求"不要代码围栏之外的文字"，基线组包了围栏，DSL 组没包。
解析时必须先剥围栏再判断，否则会把格式差异误算成解析失败。
